# Asset design — 生成前に確定すること

1. `AGENTS.md`、本スキル、カテゴリ別スキル、`assets/manifest.json`、採用済み実画像を確認。読めない資料を読んだと主張しない。
2. カテゴリを繰り返しタイル / 床装飾 / 独立オブジェクト・建築 / キャラクター・NPC / 背景へ分類。村・マップチップ・NPC・キャラには `../create-grid-map-art/SKILL.md` を併用。
3. **素材契約**を確定: 用途・素材ID・参照原画・視点・光・ゲーム中の占有セル（該当時は32×32px基準）・最終画像寸法・接続方向・背景透過・余白・接地アンカー・衝突・遮蔽・出力先。
4. 先に既存画像を調査し、切り抜き・透過修復・縮小・色補正・対称デザインの反転で済むなら**新規画像生成をしない**。
5. 生成が必要な場合だけ該当テンプレートを埋め、要求仕様の矛盾を解消してから原則1回の主生成を実施。確認のための別画像を勝手に生成しない。
6. 生成・加工後は実ピクセル寸法、RGBA透過、輪郭、余白、視点・光源、接続方向、接地、実ゲームでの見た目を確認。失敗時は加工修正を先に検討し、再生成を自動で繰り返さない。
7. 承認前のものは `work/` の候補。承認後にだけ `assets/` と台帳へ登録。素材QA・実ゲーム描画・GitHub反映・Pages・iPhone Safariの実機確認を別々に報告する。

## GitHubへの画像・原本バイナリの直接登録（成功実績あり）
- バイナリファイルがChatGPTの作業環境にありGitHubツールから読めないときは、まずBase64テキスト化し、ChatGPTライブラリの一時フォルダにアップロードする。
- `files.read` で**全行**を読み取って改行を除去し、GitHubの `create_blob({encoding:"base64",content:<実データ>})` に渡す。入力文字数・データ完整性・転送先Blob SHAを元ファイルと照合する。
- 登録したBlob SHAを使って `create_tree` → `create_commit` → `update_ref(main,expected_sha=元HEAD,force=false)`、その後にGitHub上の実体を再取得して検証する。
- 成功を確認したら一時ライブラリの `.b64` を削除する。**Canva等の無関係な外部サービスを無断の転送経路に使わない。**

**禁止:** 未承認のものを完成品と呼ぶ、仮の市松画像を実透過PNGと呼ぶ、PNGの輪郭をそのまま通行判定にする、旧リポジトリの承認情報を無確認で引き継ぐ。
