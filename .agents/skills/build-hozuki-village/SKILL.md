# 鬼灯村の制作・歩行検査

建物の透過素材から、緋月の通行・屋内外の往復・NPCとの会話までを組み立てて検査する。建物の絵柄を変更したら、対象の遮蔽と通行を再検査する。室内・NPC・配信版を引き継ぐときは[制作手順と再現方法](../../../docs/VILLAGE_MAP_WORKFLOW.md)を参照する。

## 着手前

- [共通規則](../../../AGENTS.md)、[素材管理方針](../../../docs/REPOSITORY_POLICY.md)、[採用台帳](../../../assets/manifest.json)と素材の現物を確認する。画像の生成・加工には[共通画像制作](../asset-design/SKILL.md)を併用する。
- [緋月の制作手順](../hizuki-character/SKILL.md)と[歩行の現行設定](../../../data/characters/hizuki-walk.json)から、村用の画像と足元アンカーを確認する。建物の大きさは緋月と入口を並べて決める。ゲームの32px格子、原画のコマ寸法、歩行検査ページの連続座標を区別する。
- 必要な入口、通路、背後への経路を先に決める。複数棟の配置では既存の動線と対象外の建物を保ち、必要な余白を確保する。格子マップに採用するときは配置を `data/maps/` に記録する。

## 1. 参照したものと今回の判断を記録する

1. 参照資料は一覧だけで済ませず、個別マップの画像を開く。見たマップ名、URL、比較した位置や矩形、観察事項、今回取り入れる点を記録する。屋根・壁・入口の比率は対象範囲を明記し、別の建物に共通する寸法として扱わない。
2. 「公開画像で観察」「ROM・仕様資料で確認」「今回の制作判断」「自作試作で検証」を区別する。ROMについては実際に確認した版・箇所・方法を記録する。既存の解析資料だけを読んだ場合は資料名を示し、ROM未解析なら未解析と記録する。
3. 『天外魔境ZERO』の先行調査では、村の民家で屋根・軒の面が大きく、正面の壁が低い構成を確認した。大虎町では地面・建物・一部を手前に重ねる要素の別パネルが確認できる。パネルの再合成は画像の構造を確かめる材料に使い、通行や遮蔽が切り替わる条件は自作試作で検証する。
4. 参照画像は視点、比率、輪郭、前景レイヤーの設計に使う。ゲーム配布物とPagesには自作の素材を使い、参照画像の画素やROMを同梱しない。

| 比較対象 | 見る箇所 |
|---|---|
| [Exit Village](https://www.spriters-resource.com/snes/tengaimakyouzerofareastofedenzerojpn/asset/231976/) | 民家の屋根と正面の比率、前景パネル |
| [Splendid Village](https://www.spriters-resource.com/snes/tengaimakyouzerofareastofedenzerojpn/asset/231641/) | 茅葺きの量感、正面の壁と入口、前景パネル |
| [Big Tiger Town](https://www.spriters-resource.com/snes/tengaimakyouzerofareastofedenzerojpn/asset/231576/) | 瓦屋根と軒、地面・主画面・前景の分け方 |

## 2. 建物を独立素材として仕上げる

1. 既存素材と採用台帳を確認し、流用できる箇所を決める。新作は建物1棟の透過RGBA PNGを原本にする。出入口、地面との接点、屋根の向きと見下ろし角、画面内の大きさを既存棟と揃え、緋月と並べた表示倍率で見比べる。村全体の絵やCanvasで描いた検査画面を、建物素材の代わりにしない。
2. まず1棟を単体で通して検査する。屋根だけ視点が合わない場合は、壁と入口の位置や画素を保持して屋根を直す。全体の描き直しや他の棟への展開は、原因を確認してから行う。
3. 完成した `house.png` から、緋月の手前に出る軒の薄い帯を `eave.png` として切り出す。`house.png` は軒を含む完全な絵のまま保存する。切り出しの矩形は建物画像左上からの `[x, y, width, height]` で記録し、元画像の同じ矩形とRGBAが一致することを確認する。屋根を修正した場合は、同じ原本から軒を切り出し直す。
4. 透過PNGと配置データをセットで渡す。最低限、画像パス、原寸、入口の接地位置、軒矩形、通行を止める範囲、裏側に回ったと見なす境界、入口の起動範囲、屋外への復帰位置を記録する。出入りしない建物では起動範囲と復帰位置を「なし」と記録する。建物ローカル座標とマップ座標を区別し、配置時に変換する。承認前の素材は `work/` で扱い、採用時は [リポジトリの素材管理方針](../../../docs/REPOSITORY_POLICY.md) に従う。

## 3. 描画順・当たり判定・入口を調整する

| 状態 | 描画と動作 |
|---|---|
| 正面 | 建物の上に緋月を描く。軒下に足元が入った間だけ、元と同じ位置に軒の切り出しを重ねる。 |
| 側面から裏 | 緋月の足元が裏側の境界を越えたら建物を上に描く。軒の切り出しは表示しない。 |
| 裏の当たり判定に接触 | 足元を止めて緋月の頭を一部残す。裏道は左右どちらからも入って反対側へ抜けられる幅を確保する。 |
| 正面から入口へ | 壁の当たり判定を保ち、正面から歩いた足元が入口に接触したときに入場する。退出時は同じ棟の入口の手前に戻し、その位置から移動を再開できることを確認する。 |

足元アンカーを移動・衝突・描画順の基準にする。衝突範囲は屋根を含む透明PNGの輪郭から作らず、建物の設置位置と通路幅に合わせて設定する。裏から屋根に最も近づける足元位置を求め、重なりの深い箇所で立ち姿と全歩行コマを確認する。緋月が完全に消える場所があれば、裏側の当たり判定を屋根の奥へ広げる。調整後は屋根の左右端も含めて裏道の往復と入口の通過をやり直す。足元の大きさと操作余裕を含めた通路幅を残す。

## 4. NPCと室内を組み込む

- NPCの髪型や衣装を既存資料から確認し、緋月と既存NPCに並べて頭身、輪郭、色のまとまりを合わせる。採用済みの歩行シートは台帳のパスと画像を照合して再利用する。新規制作時は、方向・列・足元が揃うように書き出し、左右の足が交互に出るかを歩行表示で確認する。
- 建物IDと間取りIDを対応させる。店番の画像は店で共有し、表示名と台詞は間取り側に置く。カウンター前の会話地点、NPCの足元の衝突、家具による遮蔽をそれぞれ設定する。入口から会話地点まで到達し、会話後に出口へ戻れることを確認する。
- 帳面などの小物は緋月と店番の見かけの寸法に合わせる。アトラスの一部を直したときは、対象範囲外のRGBA、家具の接地位置、衝突範囲を前版と照合する。

## 5. 単体、複数棟、iPhoneの順に検査する

| 順序 | 合格条件 |
|---|---|
| 素材 | 実際に透明な背景、画像サイズと接地位置の記録、建物と軒のRGBA一致。並べたときの視点と縮尺も確認する。 |
| 単体 | 正面・軒下・左右・裏で描画順が自然に変わる。裏で最も近づいても頭が残り、左右から往復できる。入口の起動と同じ棟への復帰を確認する。 |
| 複数棟 | 各棟の左右と裏を通れ、隣の建物が通路や入口を塞がない。別棟の前景や入口が誤って反応しない。 |
| 配信 | 対象ブランチとパスが承認範囲内か確認する。配信を待ち、HTTP 200と期待する版・配信内容を照合してから、コミット短縮SHA付きのPages URLを渡す。 |
| iPhone Safari | 縦持ちで表示と方向ボタンを確認する。押し続けて移動し、指を離す・指を外へずらして離す・画面を離れて戻る操作で移動が止まることを確かめる。裏の頭の見え方と入口の往復を実機で確認する。 |

画面には方向ボタン、リセット、判定表示を用意する。判定表示で足元・衝突・入口を確認できるようにする。iPhoneでは押し続けたときに画面スクロールや長押しメニューが移動を妨げず、指を離したときや入力が取り消されたときに保持状態を解除する。

報告には、素材検査、歩行検査、配信したSHA・URL、iPhone実機、素材採用の状態を個別に書く。ローカル自動検査とiPhone実機の結果は区別する。検査用の部屋は出入りの試験に使い、本編の室内や素材の採用は別工程で扱う。

## 確認済みの基準例

- 鬼灯村全体を再現するときは[屋外・室内・NPCを揃えた固定版](../../../docs/VILLAGE_MAP_WORKFLOW.md#固定版を再現する)を使う。台帳を持つ `main` と、検査ページを配信する `gh-pages` の役割を確認する。
- 藍瓦の民家・茅葺きの民家・茶店・宿を、単体と4棟配置の両方で切り替えられる。[iPhone用Pages](https://hihosir.github.io/kikokuno-hanamusubi/previews/village-building-walk/?v=c7e3398) · [固定版のソース](https://github.com/HiHoSir/kikokuno-hanamusubi/blob/c7e339827d165ae8b0d9b993769b7d9f548ee75b/previews/village-building-walk/index.html)
- 固定版HTMLの `cases` に建物4棟の設定と透過PNGが入っている。`house`・`entrance`・`blockers` は単体検査のワールド座標、`eave` は建物画像からの相対矩形。PNGのBase64データはローカルで展開できる。採用素材を探すときは台帳を先に確認する。
- 基準例では緋月は1コマ80×112 px、足元アンカーはコマ内の `(40, 106)`。裏側の衝突範囲は屋根画像の上端から96 pxで始まり、足元の判定半径8 pxにより、屋根上端から約88 pxで緋月が止まる。これは連続移動の検査ページで使った数値。新しい建物や格子マップへの組み込みでは、絵と移動方式に合わせて再計測する。
- この基準例の配信元は `gh-pages` の `previews/village-building-walk/index.html`。更新時は現在の配信設定を確認し、別パスを追加する場合は公開検証用プレビューの承認範囲を確認する。
