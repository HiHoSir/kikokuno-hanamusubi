# 『鬼哭の花結び』戦闘システム（本編・B式v2）

## 正本・構成
- **正本は `HiHoSir/kikokuno-hanamusubi`。** 旧 `yaksha-hanamusubi` の `js/game.js` 等の実装は採用しない。
- 主人公は緋月1人。戦闘は `src/game/battle/index.html` + `rules.mjs` + `walk.mjs`。親 `src/game/index.html` と `src/game/navigation/game-shell.mjs` に統合し、BGMは親ページが管理する。単独の別タブ戦闘／追加検証HTMLを設けない。
- フィールドでは歩行完了9〜13回を目安に敵1〜2体と接敵。村・天妖の社への入口接触時やはしご中では接敵しない。勝利・逃走後はフィールドへ戻り、敗北時は鬼灯村へ戻る。
- フィールドに現在採用済みの通常敵画像は `assets/enemies/{field-oni,tanuki,onibi}.png` の3種類（`assets/manifest.json` 参照）。野の小鬼1体／化け狸2体／鬼火1体を使用。化け狸は個別の体力を持ち、攻撃標的を選べる。**未接続の地域へ旧作品の敵を勝手に追加しない**。
- 第一ルート（鬼灯村→天妖の社）の実際の地形道路 `YK_WORLD.roads[0]` から出現帯を決定。道の前半は野の小鬼55%・化け狸2体45%、後半は野の小鬼20%・鬼火45%・化け狸2体35%。道から外れた未接続地域には前半の安全な敵のみ登場。詳細の試算は `docs/BATTLE_BALANCE.md`。
- 緋月の戦闘ポーズは `assets/characters/hizuki/battle/` の6画像（待機・物理攻撃・術・被弾・防御・勝利）。左右二分割のコマンド・状態パネル、上下左右キーとA/Bは継続。

## 戦闘画面の採用デザイン（2026-11-13・ユーザー選択）

**画面方向で2案を併用することを決定：横画面＝案A、縦画面＝案B。** この選択はUIレイアウトの採用であり、生成画像に描かれたキャラの外見・背景・数値・アイテム・敵の組み合わせを正本として採用する意味ではない。

### 横画面：案A
- 上部の広い戦場に緋月の背面像を左、出現敵を右側へ横並び配置。対象中の敵に三角カーソル／枠を付け、各敵の足元に区別できる名前を表示。
- 画面下の情報帯は**左に5項目の縦コマンド**（たたかう／術／道具／防御／にげる）、**右上に緋月の状態**（段／体力／技）、**右下に横長の戦闘メッセージ**。ステータスは1人分だけ。
- 案Aの良さは「戦場が広く、見せ場と操作領域が分かれる」点。ゲームタイトルの大きな見出しや「案A」のラベルは画像比較用で、本編には表示しない。

### 縦画面：案B
- 上部55〜60%程度を戦場として確保し、緋月背面＋複数の敵を1画面内で見せる。敵の個体ごとに足元の名前や選択表示を用意する。
- 戦場の**下に左コマンド／右緋月ステータスの2カラム**を配置し、最下部に横長のメッセージ欄を置く。ステータスの基本表示は**名前・段・体力・技**。金額や攻・守などの詳細は通常コマンド時に常時大きく表示しなくてよい。
- 片手のタッチ操作を考慮し、各項目と標的のタッチ領域を確保する。iPhoneのsafe-area、画面高の違い（小型画面やアドレスバー相当領域）でも戦場・コマンド・状態・メッセージが欠けないよう検証する。
- 案B画像に描かれた**黒〜紫の長髪、花の髪飾り、違う和装、顔立ち**は緋月の正本ではなく、採用禁止。どちらの向きも現行戦闘6ポーズと `docs/characters/HIZUKI_CANON.md` に一致させる。緋月は**水色ショートボブ・中央の金角1本・赤白の装束**。

### 共通のレイアウト／操作規則
1. **戦闘ロジックは1つ**。CSSレイアウトのみ方向によって切り替え、敵体力・ターン・入力状態・音楽・表示メッセージを方向変更でリセットしない。親ページのBGM責務を変更しない。
2. 敵1体、同種2体、異種2体を最低限のレイアウト検査ケースとする。将来3体にも拡張可能な並びを設計するが、現行ゲームは最大2体。画像案にある「化け狸＋鬼火＋化け狸」など3体の同時戦はまだゲーム仕様として確定していない。
3. 標的カーソルは**現在選択中の1体だけ**を明瞭に強調し、同名の敵には①②などの識別番号をつける。タッチ選択と上下左右＋A/B操作は同じ選択状態を共有。戦闘メッセージと選択メニューが敵画像を覆いすぎないようにする。
4. **術・道具は一時的なサブメニューへ切り替える**。両方向とも、階層を増やすためだけに多数の枠を常時並べない。メニューから戻る操作はB、決定はA。
5. 窓は同じドット密度の暗色フレーム／控えめな和風装飾、フォントは既定のDotGothic16に統一。横と縦でフォント・色・カーソル・枠のデザインを共通化する。生成モック画像の極端な描き込みをそのまま本編へ移さない。
6. 背景と敵画像は**現行承認素材を優先**。AI生成の比較画像にある未登録の敵・フィールド背景を採用済み素材として扱わない。画像ファイルを `assets/` や `source-assets/` に勝手に複製しない。

**本編実装状況（2026-11-13更新）：** `src/game/battle/index.html`・`battle.css`・`walk.mjs` に横＝案A／縦＝案Bを反映。レイアウト切替はCSSの `@media(orientation:landscape)` だけで行い、バトルモジュールを再起動しない。2体の同名敵はそれぞれ個別の名前表示と標的フレーム／▼がつき、敵画像を直接タップするかD-pad＋A/Bで選択できる。現在の現物戦闘UIは1人の状態表示と5コマンドを維持する。

**表示上の調整：** 縦画面は戦場の下に左コマンド・右ステータス、その下に横長メッセージ、最下段にタッチ操作パッド専用スペース。横画面は戦場を広く取り、下部中央の左コマンド／右上ステータス／右下メッセージ。操作パッドは左右の余白に分離し、情報パネルを隠さない。体力・技の表示は既存の状態値に連動。画面の装飾は新規アセットを増やさずCSSで調整した。

## 戦闘背景と命中演出（2026-11-13追加）

- **草原用戦闘背景（2026-11-13追記）：** ユーザーが選んだ高ドット感の草原イラストを384×216px／64色PNGに加工し、`assets/battle/backgrounds/grassland.png`（台帳ID `battle-background-grassland`）へ登録。`data-battle-terrain="grassland"` のときだけ表示する。今後は地形別セレクタと素材を追加して切替可能とするが、現段階で草原以外の戦闘背景は登録しない。`image-rendering:pixelated` を使用し、新規画像に文字・戦闘キャラ・UIを焼き込まない。旧フィールド遠景を利用したCSSは草原以外の暫定背景として維持する。緋月6ポーズと承認敵3種、戦闘ロジックは変更しない。
- 戦闘ロジック（B式v2・敵体力・報酬・行動順）は変更せず、**緋月の攻撃ポーズ（0ms）→標的への命中（約95ms後）→斬撃エフェクト終了→敵の反撃で緋月が被弾ポーズ（約570ms後）→勝敗と体力／技の最終描画（約1060ms後）**の順に表示する。敵の体力が0になっても命中エフェクト開始前に画像を消さない。
- 物理は斜め交差の斬撃、術は小さい光輪、緋月の被弾は体の周囲だけを明滅。画像を単純拡大した別アセットを作らず、`index.html` 内の `impact-effect` と `battle.css` で統一する。
- 縦画面では斬撃・光輪を**実際に見える敵画像の足元寄りの領域**へ揃える。画像の透明領域上端に浮かせない。標的決定と同時に標的枠を非表示へ戻し、異なる敵が選択状態のまま命中エフェクトを受ける誤表示を防ぐ。
- ゲーム内の戦闘コマンド・戦闘状態・遷移・親ページのBGM責務は従来どおり。短い戦闘メッセージ枠で攻撃文と複数敵の反撃文を連結して切らないよう、時間段階に合わせて表示する。
- `tools/qa-battle-browser.mjs` が横2サイズ・縦2サイズで、1体／2体、攻撃中に敵が残ること、物理エフェクト・反撃を表すDOM状態、縦の斬撃位置、標的枠が消えること、2体目だけ倒せることを実ブラウザで確認する。Chrome QA成功：<https://github.com/HiHoSir/kikokuno-hanamusubi/actions/runs/43395597643>。スクリーンショットはActionsの `battle-browser-screenshots` に保存。
- **ポーズ対応と演出の分離（2026-11-13再検査）：** `attack.png` は攻撃が命中するまで、`hit.png` は敵の反撃を受けた時だけ使用する。旧表示では95ms後の斬撃（約410ms維持）と225ms後の被弾が重なっていた。反撃を570ms後へ遅らせ、Chrome検査で攻撃中は `attack.png`、反撃中は `hit.png`、被弾中は斬撃エフェクトが消えていることを確認。検査結果：<https://github.com/HiHoSir/kikokuno-hanamusubi/actions/runs/43398826042>。

## 敵画像のドット感（2026-11-13追記）
- **新しい敵画像は生成しない。** 採用済みの野の小鬼・化け狸・鬼火のPNGはそのまま保持し、戦闘画面に表示する際にブラウザのCanvasで最大64pxの粗い格子へ縮小する。表示時は `image-rendering:pixelated` で最近傍拡大し、原画のデザイン・透過・足元位置・アセット台帳・IDを変更しない。

## B式v2：確定数値
数値正本は `data/characters/hizuki-status.json`、実行時の定数は `src/game/battle/rules.mjs` 内の `STATUS_V2` に対応。自動検査で不一致を検出する。

- 段1：体力26／技12／攻9／守6／はやさ9。固定成長は段ごとに体力+8、技+1.3、攻+2.6、守+1.6、はやさ+2。総値を四捨五入（ブレなし）。
- 物理ダメージ＝`floor(攻/2−守/4)`、乱数±1/16、最低保証は攻の約10%（最低1）。
- 段数上限99、最終ボスの想定段40。次段までの心＝`round(80×段^1.35)`。段アップで体力と技が全回復する。
- T0〜T6の武器＋防具合計補正はB式v2として確定しているが、**個別装備の識別子・販売内容・店の解放条件は未実装**。現在はT0で開始。戦闘データ構造は将来のtierとイベント覚醒を保持できるが、実際の装備更新は販売システムができてから。
- 第一覚醒：体力+20／攻+8。第二：守+8／はやさ+6。覚醒は段数ではなく物語イベント発生であり、**現在はイベント未接続**。第三覚醒は能力値未確定。
- 敗北時：所持両25%減（切り捨て）、体力と技を回復し最後の町へ帰還。現段階で実装済みの町は鬼灯村のみ。

## 戦闘コマンド
- **たたかう**：B式物理ダメージ。敵2体の場合は標的を選択。各敵は体力を独立して保持し、生存している敵がそれぞれ反撃する。
- **術**：現在実装した最低限は「糸遊」（段3から、固定威力30、技3、単体）と「つむぎ」（初期習得、体力の30%回復、技5）。**12術全体の採用・実装ではない**。候補は `docs/SPELL_CANDIDATES.md` に別途保全してあり、議論はいったん休止。
- **道具**：薬草で体力26回復、使用したときのみ個数減。
- **防御**：敵から受ける物理ダメージを約半減。
- **にげる**：はやさに応じて70〜85%成功。失敗時は敵の反撃。術力・道具が不足、体力満タンの回復は手番を消費しない。
- 回復の先手、状態異常、覚醒術の演出、ボスの予告攻撃、装備店は今後の工程。未実装項目を完了と呼ばない。
