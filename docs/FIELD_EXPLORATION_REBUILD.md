# フィールド探索・地形再構築：第一次実装と監査

対象：`HiHoSir/kikokuno-hanamusubi` の80×80／32pxフィールド。既存タイトル、村、天妖の社、川・海、橋、進行先の位置、カメラ・水面描画、採用アセットは変更しない。

## 全域点検で判明したこと

- 従来の地形には1〜3マスだけ突出して独立する高さ成分が点在。孤立した崖は連続する斜面に見えない。
- 東の大きな高台（x62〜76、y26〜42）は、地形上約160の高台マスがあっても、従来は到達可能マスが0。
- 中央の山塊（x23〜32、y34〜40）は54マス程度の高台だが、旧描画では山素材を隠している一方、地形の mountain 判定が残り、到達可能マスはほぼなかった。**視覚と通行判定が食い違う**。
- 森の高台など通れる高台もあるため、一律の高さ除去や全山岳通行化はしない。

## このブランチの改修

1. 東側の大きな高台へ、草地の坂道2か所を接続。森林を一部開いて見通しのある草地を作り、既存の野花で小さな景観上の発見を添える。
2. 中央の旧山塊は描画対象の草・森と通行判定を一致させる。地形タイルのみ約46マス置換し、回り込める坂道を2か所追加。既存の山脈全体の通行判定は変えない。
3. 1〜3マスの孤立した標高のみ、ランドマーク付近を除いてモデルの共通処理で平坦化。川や地表素材は変更しない。
4. 既存の`wildflowers`素材を15か所に増設。木陰の見晴らしを妨げていた非衝突の木を11か所整理。
5. 前段でレビューした南・東・西から登れる2段高台と、北側の1マス踏み跡はそのまま維持。

## 検証指標

- 東高台の到達可能領域：0 → 148マス
- 中央高台の到達可能領域：ほぼ0 → 55マス
- 全体到達可能マス（地形導線＋通行可能セル）：2222 → 2424
- 新設・修正した坂道のすべてが0/1差の地形制約を満たし、`YK_ELEVATION.validate` はエラー0
- 独立した1〜3マスの高さ修正で変更されたランタイム標高セル数：9

これは**全フィールドの完成宣言ではなく第一次の地形修復**。見た目の整合性とiPhone Safariでの確認前に、本編 `main` のマップデータは採用しない。

## 山オブジェクトの間引き（斜め崖の視認性検査）

高台の斜め崖が山オブジェクトに隠れる箇所から、承認済み山オブジェクト16個を削除。北部の山並み・北東の山沿い・南の高台の周辺を対象とし、隣接する山オブジェクトを残して山脈の連続性を保つ。

- 山オブジェクト接地セル：(52,22)、(54,24)、(55,25)、(57,26)、(65,15)、(68,15)、(66,16)、(68,16)、(70,18)、(44,64)、(42,65)、(46,66)、(42,67)、(64,8)、(65,9)、(68,8)
- 基底地形はすべて通行不能の `mountain`。標高、道路、川、海、坂道のグリッド情報は不変。
- ソース山オブジェクト数181→165。ランタイムの山描画数110→98、山由来の木描画数も7減。
- プレビューとブラウザQAで視認性を評価し、本編採用は保留。
