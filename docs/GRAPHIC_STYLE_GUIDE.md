# グラフィック生成・検査の共通基準（第1作『鬼哭の花結び』）

本書は **制作前の分析 → 生成／加工 → 検査 → 採用判断** を再現可能にする仕様。画像生成ツールや [The Spriters Toolkit](https://tools.spriters-resource.com/) の「分割・パレット分析・シート化・比較」という着想を参考にしているが、ツールの出力を自動的に画風の正解とは扱わない。参照ゲームの画像をコピーせず、構成・技法の研究に限定する。

## 0. 適用順位と範囲

1. `AGENTS.md`、`.agents/skills/asset-design/SKILL.md`、`assets/manifest.json` と **採用済みの実画像**を確認。
2. 緋月の外見は `docs/characters/HIZUKI_CANON.md`、コマ順・接地は `data/characters/hizuki-walk.json` を最優先。NPCの縮尺は `tests/nonfield-world-scale.test.mjs` に対応。
3. フィールドのみ **地形1セル32×32px**。フィールド用SD緋月も32×32px/コマ。**鬼灯村・室内・天妖の社・洞窟・入り江には32pxグリッドを押し付けない**。
4. 非フィールドの人型歩行は既存の **80×112px/コマ、3列×4行、足元(40,106)** を基準とする。背景・家・小物をこの人物との **ワールド座標上の相対寸法**で作る。人物や建物だけを独立拡大・縮小して「合わせる」のは禁止。カメラ設定も素材寸法と混同しない。
5. 既存の採用済み表示、接触判定、遮蔽、音・ゲーム進行を、グラフィック解析だけを根拠に変更しない。天妖の社の試作と本編採用の区別は `docs/TENYO_SPRITE_REBUILD_V1.md` を確認。

## 1. 画風の数値化：測るものと測れないもの

| 特徴 | 計測・記録方法 | 採用時の判断 |
|---|---|---|
| アトラス寸法とコマ割り | PNG寸法、行列、各コマの可視矩形 | 用途別の**契約寸法**と一致するか |
| 色・色数 | 可視画素のユニークRGB数、頻出色 | 同カテゴリの採用画像と比較。多ければ悪いとはしない |
| 透過・余白 | 可視/半透明画素数、上下左右の透明マージン | 足元・重なり・アニメで意図どおりか。余白末端を地面と誤認しない |
| 画素のまとまり | 近傍4方向と接触しない可視画素数 | 孤立画素・ノイズの**手がかり**。目・火花・水しぶきは例外になり得る |
| 頭身・画素密度 | 画像を実等倍で並べ、頭/胴/足の比、輪郭太さ、塊のサイズを記録 | 生成画像を縮小・自動減色しただけの細密さをドット絵品質と誤認しない |
| 変更画素 | 同じ寸法の修正前後でピクセル単位の差分を算出 | 修正要求外の領域・向き・色まで変わっていないか確認 |
| 重なりと接地 | 透過可視最下端、見た目の接地、別定義の衝突領域を照合 | 屋根・柱・岩・足元の前後関係は**実際に歩いて**判定 |

**禁止：** 未測定なのに「最大16色」「2px輪郭」「縦横32px」等の閾値を画風ルールとして捏造しない。正式な数値範囲は、同じカテゴリの複数の採用実画像の測定と人による比較・承認がそろってから決める。SFC期らしい陰影段数や色の作り方は観察対象であり、機械的な全素材共通の固定値ではない。

## 2. 参照画像の選び方

- **主人公・NPC:** `assets/characters/hizuki/walk-4dir-80x112.png`、`assets/characters/npc/` の同形式PNG、緋月の正式原画 `source-assets/characters/hizuki/character-design.jpg`。この3者はそれぞれ「外見正本」「ゲーム中の表示」「同種との画風比較」という役割を混同しない。
- **建築・家具:** `assets/village/scene/`、`assets/village/interiors/` の採用中画像と、対応する `data/maps/hozuki-village/scene.json` を人物と一緒に比較。ドア・柱・畳・家具の接地を照合する。
- **地形・水・社:** エリアごとの採用素材と現行描画を比較。天妖の社の候補 `assets/tenyo-rebuild-v1/` は、ユーザー合格が未確認なら**採用済み画風の基準に昇格させない**。
- **外部参照:** 『天外魔境ZERO』等は遠近の取り方、パレットの考え方、地形のつなぎ、遮蔽分割の**技法**を分析する。元のピクセル・キャラクター・タイルを流用しない。出典URLと観察内容を制作メモに残す。

## 3. 生成前に作る「素材契約」

次の欄を埋めないまま画像を生成しない。未確定値は「未測定」「要目視」と記し、推測で決めない。

- **対象・用途:** 素材ID、使用画面、キャラ／地形／独立物体／背景の分類
- **比較対象:** 採用済み画像のパス・評価する部分（色／輪郭／頭身／陰影／画素の大きさ）
- **生成単位:** 1素材、透過コマ、アトラス、接続タイルのいずれか。必要な方向・ポーズ・行列
- **寸法契約:** 画像全体px、各コマpx、ゲーム内のワールド占有。**32pxの制約はフィールドのみ**
- **絵柄:** 実等倍の輪郭・陰影塊・色・ディテール量の比較観察。「参考画像と一致」だけの曖昧指示は禁止
- **幾何:** 基準視点、光源、人物との相対寸法、ドア高さ、接地・透過余白
- **独立した実装項目:** 当たり判定、見た目の接地、遮蔽の前後、入口や通路、水・煙のアニメ
- **採用条件:** コマ欠けなし、向きの整合、目視比較、実ゲームでの前後関係、横画面表示の確認

### カテゴリ固有の契約
- **4方向歩行:** 3列×4行、行は前・後・右・左、列は待機・歩行A・歩行B。左右の足と腕の手前／奥を確認。停止時の直立、コマの接地位置を合わせる。緋月は公式外見を固定する。
- **フィールドタイル:** 32×32pxの地形契約、辺・内外角・分岐を一組で設計。3×3に並べて継ぎ目と反復を検査。水面は地形と独立した時間変化を確認する。
- **建物・社・家具:** 画像を32pxに押し込めない。人物と並べて扉・屋根・家具の高さを確認。接触判定と描画の重なりは別定義で管理。透過の最下行を機械的に接地点にしない。
- **エフェクト:** 連続コマのリズムと接続を検査。半透明や孤立画素を一律に除去しない。

## 4. PNG画像の再現可能な分析

Node.js 20以上で追加パッケージ不要。スクリプトは**読取り専用**で、画像の保存・変更・圧縮・採用登録はしない。

    node tools/analyze-sprite.mjs assets/characters/hizuki/walk-4dir-80x112.png --frame 80x112
    node tools/analyze-sprite.mjs assets/characters/hizuki/walk-4dir-80x112.png --frame 80x112 --json
    node tools/analyze-sprite.mjs work/candidate.png --frame 80x112 --compare work/before.png --json

出力はコマごとの行列、可視画素の範囲と透明余白、色数、半透明画素数、孤立画素数、頻出色。`--compare` は**同じ画像寸法同士**の変更画素数を各コマで記録する。**異なる画像の画風の似かよいは判定しない**。

対応範囲: 非インターレースの一般的なPNG（RGBA/RGB/グレースケール8bit、インデックスPNG 1/2/4/8bit）。16bit PNG・Adam7インターレースには非対応。非対応形式はエラーにする。外部ツールの分析値と数値が同じであることは保証しない。

## 5. 検査・修正と最終採用のゲート

1. **比較**: 同用途の採用素材を選択し、サイズ・色・可視領域・ドットの塊を数値と等倍の画像で比較する。
2. **候補生成／加工**: 既存PNGの修復・反転・透過調整で済むなら再生成しない。必要時だけカテゴリ別テンプレートから**実素材**を生成する。比較スクリーンショットを実装成果と偽らない。
3. **静的検査**: コマ数、RGBA、余白、頭身、足元、パレット、左右対称、アトラス境界。単に「色数が少ない」だけでは合格にしない。
4. **配置検査**: 使用先の正しいワールド倍率で緋月、既存NPC、建築と一緒に表示。地面との接地、物体の前後、浅瀬の通行、透明余白による遮蔽の誤認を確認。
5. **回帰**: `npm test` と、変更した画面の専用ブラウザQAを実施。GitHub Actions成功、GitHub Pages公開、iPhone Safariでの目視合格は**別々に記録**。
6. **採用**: ユーザーの承認後に既存安定パスを置換し、`assets/manifest.json` と参照を同期。未承認の候補はGit管理対象外の `work/` に留める。

**本書の導入時点では、既存画像・ゲーム描画・衝突判定・カメラは変更しない。** この文書と検査ツールの存在は、現行アセットの全件分析済み・画風合格・本編反映済みを意味しない。
