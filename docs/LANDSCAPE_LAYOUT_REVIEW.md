# 横画面専用 — カメラ・HUD・操作のレビュー

更新: 2026-11-14。第1作『鬼哭の花結び』の現行基準。

## 共通
- プレイ方向は横画面だけ。縦向きでは回転案内を表示し、進行状態と音声を再生成しない。
- 実ブラウザ検査サイズは844×390、900×390、1536×706。iPhone Safari実機テストとは区別する。
- 景色に合わせてカメラの視野を横へ広げ、キャラ・タイル・建物を個別に横方向へ伸ばさない。
- D-pad左下、A/B右下。透明の操作レイヤーを風景に重ね、108pxの不透明帯で表示面を潰さない。
- 32pxのフィールド移動格子、当たり判定、緋月の原寸、BGMを変えずにレイアウトを調整する。

## フィールドの再発防止
- 表示サイズに合わせるのは src/field/viewport.mjs の fieldViewportDimensions。論理高544px、描画幅=実際の表示比率に応じた値。
- src/field/runtime.mjs がカメラ幅を src/field/landscape.js と src/field/elevation-view.js に渡す。地形、崖、海、NPC、緋月は同じ投影を使う。
- CSS object-fit:cover や正方形バッファの中央切り抜きは行わない。雲は地形と同じ横幅を覆う。
- 空の既存640px画像は中央で原寸描画、左右を反転して接続する。繰り返しの目立つ継ぎ目や端列の横縞を作らない。
- 画面を横へ広げた結果の描画負荷はiPhone Safari実機で要検証。

## コマンド操作の統一（2026-11-14）
- メニューには親画面側に専用のD-padとA/Bを重ねる。ゲームシーンのiframeはメニュー中にpointer-eventsを無効化するため、移動操作が漏れない。
- 左のコマンドは上下で切り替え、右またはAで選択可能な道具・術・設定の詳細へ移る。詳細は上下で選択し、Aで使用。Bでコマンドへ戻り、もう一度Bでメニューを閉じる。
- 道具・術の使用は既存の戦闘プレイヤー保存データに反映。BGMは親画面が維持し、セーブ未実装の『記録』は選択不可。
- タップ・キーボード（矢印・Enter／Space・Escape）でも同じ動作。回転時にはメニューを閉じ、移動入力は再開しない。

## 横画面のタッチ操作領域（2026-11-14）
- 既存の156px四方向パッドを0.72倍にすると1方向あたり52×0.72＝37.44pxになり、iPhone横画面で押しにくい。共通コントローラ・フィールド・戦闘の横向き倍率を0.85へ統一し、各方向52×0.85＝44.2pxにする。
- 親コマンドメニューの専用パッドは1辺44pxの実サイズとし、縮小を行わない。大きさのみ調整し、フィールドのキャラ倍率・カメラ・衝突判定には触れない。ノッチ・画面端・会話ボックスとの非重複はChromeとiPhone実機で継続確認。

- 共通UIの回帰防止：`src/game/ui/controls.css`・親ゲームの`index.html`・回転案内コードの変更で、フィールド・村・社・戦闘のブラウザ検査が実行されるようGitHub Actionsのpaths条件を横断修正。従来はフィールド・戦闘QAが個別ソース変更時だけ走るため、共有CSSの変更が未検査になる欠陥があった。

## 描画時間の計測（2026-11-14）
- `src/field/?from=village&profile=1` のときだけ `window.__FIELD_RENDER_PROFILE` に1回の描画時間（実行ミリ秒、240サンプル）・回数・キャンバス論理寸法を保持。通常のプレイ中は時計取得やサンプル蓄積なし。画面上のデバッグ表示なし。
- `tools/qa-field-browser.mjs` で横3サイズの静止時・短時間移動後の描画サンプルを取得しp50/p95/最大時間をGitHub Actionsログに出す。ヘッドレスChromiumの値はiPhone Safari実測FPSではないため、参考値として区別する。

## 地形の描画回数削減検証（2026-11-14）
- 初回Chrome計測では1回の描画中央値103〜107ms。
- `CanvasPattern`塗り・9引数の画像切り出し・テクスチャ余白縮小はそれぞれ計測値が悪化したため、いずれも正本から外した。
- 新しい試行は画像処理方法を元に戻し、**段差・斜面・海岸・切り欠きのない水平タイル**だけ投影分割を2帯から1帯へ減らす。複雑な地形の描画は変更せず、カメラ・キャラ・衝突格子も維持。実ブラウザの数値が改善しなければ戻す。

- 計測値のばらつきが大きいため、同じページ・同じCanvas・同じ地形・同じカメラ・同じ画像キャッシュを使い、元の地形分割（16px）と平坦タイル32px案を交互に10回ずつ描く**同一実行内A/B検査**を追加。p50と比率をログに記録。独立したCIジョブ間のp50だけで採否を判断しない。

## 描画時間と非表示時の処理停止（2026-11-14）
- Chrome同一実行のA/B実測では、元の描画に対する「平坦な地形だけ粗い投影」方式の中央値比率が0.979・1.004・0.932と小さく、見た目の精度を変える理由がないため**不採用**。描画本体は計測前の正本へ戻した。
- テクスチャを別の描画APIへ変更する案もCI計測で改善が確認できなかったためすべて不採用。描画時間計測（`?profile=1`）は引き続き利用可能。
- フィールドは縦向きの回転ガード中、および親コマンドメニューが開いている間は地形の再描画を中止する。移動入力は解除し、ステップ・位置・BGM・iframeを再生成しない。復帰した次のRAFで再描画する。
- `tools/qa-field-browser.mjs` で各横画面サイズでメニューを開いた後590msの描画回数増加が0、閉じた後の描画回復、BGMとシーンURL不変を検査。これは非表示時の負荷を抑えるものであり**移動中の100ms級の描画負荷を解決したと主張しない**。追加の基盤改善は必要。

- 追加：横画面のフィールドを縦に回した状態でも550msの描画回数が増えず、横向き復帰後は同じシーンURLとBGMが維持されることを3サイズで検査する。実iPhoneの回転ロック動作は未検査。

## 海岸ジオメトリのキャッシュ試作（2026-11-14）
- 海岸の水際形状・波状の砂浜ポリゴン・輪郭線はワールド座標で固定。毎フレーム描画のたびに`sin`や近隣標高判定を再実行せず、マップとタイルをキーに保持する。投影・描画順・アニメ水面・32px地形グリッドは変更しない。
- 検証用に`YK_FIELD_SHORE_CACHE=false`で従来の計算と描画を比較。Chromeで同じ地形・同じCanvas・同じブラウザ内の前後計測を実施。iPhone Safari実機速度の改善値としては扱わない。

- 画素比較の追加検査（Chromeの844×390・900×390・1536×706）では、新旧描画の全Canvas画素差分が**0**。アニメーション時刻を固定して検証した。
- 同一ブラウザでの速度比較は試行1で約2〜15％短縮、一方で試行2は約9％短縮〜15％悪化とばらついた。海岸形状のメモ化は映像の再現性が保証された小規模な計算削減として採用するが、**移動中のFPS改善を保証するものではない**。

## 既存マップチップの横方向チャンク比較（2026-11-14）

- SFC『天外魔境ZERO』のワールドマップ資料から、海岸・崖・土地の接続パターンという**技法のみを参照**。画像・ROMアセットはコピーしない。
- 本作には既存の32px単位8×8枚の地表合成キャッシュ（`src/field/landscape.js` の `elevationTexture`）が存在。今回の試作は追加のアセットを作らず、この完成済み画像から同一高さの内陸タイルを3～8枚の横長パーツとして事前合成し、遠近法の投影命令をまとめるもの。
- 高低差・斜面・海・海岸線・崖の縁は既存の描画ルールを維持。周囲4方向と標高が一致する安全な平坦地のみグループ化し、8×8チャンク境界は跨がない。生成キャッシュは最大64横長パーツのLRU。
- 実験フラグ `window.YK_FIELD_ROW_CHUNKS=true` のときだけ比較描画を使い、**本編のデフォルトは旧方式**のまま。GitHub ActionsのフィールドQAで同一Canvas・同一水面時刻の画像ピクセル差分と描画時間を3サイズで計測する。
- 結果はQA成果物 `field-rowchunks-metrics.json` と `field-rowchunks-baseline-900x390.png` 等に保存する。実iPhone Safari検査とは区別。

## 横方向連結チャンク試作の評価（2026-11-14）

- 実験コミットは `review/field-rowchunks` ブランチに隔離。本編の `src/field/elevation-view.js` は**試作前の正本へ復元**し、実験用レンダラや評価QAの追加は公開対象から除外。
- 元々フィールドは`elevationTexture()`によって32pxの地表タイルを8×8枚単位で静的に合成済み。問題はそれらを毎回細かく透視投影する処理。横に3〜8枚の平坦地を合成して投影する案を、同一Chromium内の旧版・候補版で比較した。
- 画面1536×706：142.25→144.30ms（約1.4％悪化、差分7.661％）。900×390：146.75→162.90ms（約11.0％悪化、差分7.235％）。844×390：139.00→152.00ms（約9.4％悪化、差分7.715％）。差分は水面時刻を固定したCanvas比較。3サイズすべて不合格のため**採用禁止**。
- 連結チャンクの計測対象は3サイズとも57区間・合計360タイル。手作りタイル画像の量産より、既存のチャンク地表の描画をGPUへ渡す構成や、パーツの接続規則を先に確定する必要がある。
- 技法参照：<https://www.spriters-resource.com/snes/tengaimakyouzerofareastofedenzerojpn/> のWorld Map群。海岸・崖の接続構造のみ参考にし、画像・ROM素材をコピーしない。
- 比較画像・計測JSONはGitHub Actions `Field browser visual QA` の run `43564181862` の成果物として保持。新たなマップチップ画像候補は承認まで`assets/`へ追加しない。

## 地形接続用32pxチップセットの試作（2026-11-14）

- 接続規則の参考は『天外魔境ZERO』のワールドマップ画像。**原作の画像・ROMデータを取り込まない**。本作の採用済み草／砂／水のテクスチャと`src/field/landscape.js`の既存`floorLayer`・`maskTile`から生成する。
- 水中心＋周囲の陸、および砂中心＋周囲の水について、**4方向の16接続（N=1,E=2,S=4,W=8）**を32×32pxで書き出す。4×4シートには左上からマスク0～15を格納。実マップの10×14サンプルも2倍ドット倍率で検査する。
- 既存の絵を加工して作る**見た目の候補**であり、速度改善・ゲーム採用を意味しない。`tools/qa-field-map-parts.mjs` をGitHub Actionsで実行し、PNGと方向のメタデータを成果物に出力。`assets/`に未承認画像を追加しない。
- 以前の失敗した横連結チャンク方式とは独立。今後は接続素材の品質を確定してから、GPU側でチャンクを描画する技術検証を行う。縦横のカメラや地形判定を安易に変更しない。
