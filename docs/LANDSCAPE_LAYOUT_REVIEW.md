# 横画面専用 — カメラ・HUD・操作のレビュー

更新: 2026-11-14。第1作『鬼哭の花結び』の現行基準。

## 共通
- プレイ方向は横画面だけ。縦向きでは回転案内を表示し、進行状態と音声を再生成しない。
- 実ブラウザ検査サイズは844×390、900×390、1536×706。iPhone Safari実機テストとは区別する。
- 景色に合わせてカメラの視野を横へ広げ、キャラ・タイル・建物を個別に横方向へ伸ばさない。
- D-pad左下、A/B右下。透明の操作レイヤーを風景に重ね、108pxの不透明帯で表示面を潰さない。
- 32pxのフィールド移動格子、当たり判定、緋月の原寸、BGMを変えずにレイアウトを調整する。

## フィールドの再発防止
- 表示サイズに合わせるのは src/field/viewport.mjs の fieldViewportDimensions。論理高544px、描画幅=実際の表示比率に応じた値。
- src/field/runtime.mjs がカメラ幅を src/field/landscape.js と src/field/elevation-view.js に渡す。地形、崖、海、NPC、緋月は同じ投影を使う。
- CSS object-fit:cover や正方形バッファの中央切り抜きは行わない。雲は地形と同じ横幅を覆う。
- 空の既存640px画像は中央で原寸描画、左右を反転して接続する。繰り返しの目立つ継ぎ目や端列の横縞を作らない。
- 画面を横へ広げた結果の描画負荷はiPhone Safari実機で要検証。

## コマンド操作の統一（2026-11-14）
- メニューには親画面側に専用のD-padとA/Bを重ねる。ゲームシーンのiframeはメニュー中にpointer-eventsを無効化するため、移動操作が漏れない。
- 左のコマンドは上下で切り替え、右またはAで選択可能な道具・術・設定の詳細へ移る。詳細は上下で選択し、Aで使用。Bでコマンドへ戻り、もう一度Bでメニューを閉じる。
- 道具・術の使用は既存の戦闘プレイヤー保存データに反映。BGMは親画面が維持し、セーブ未実装の『記録』は選択不可。
- タップ・キーボード（矢印・Enter／Space・Escape）でも同じ動作。回転時にはメニューを閉じ、移動入力は再開しない。

## 横画面のタッチ操作領域（2026-11-14）
- 既存の156px四方向パッドを0.72倍にすると1方向あたり52×0.72＝37.44pxになり、iPhone横画面で押しにくい。共通コントローラ・フィールド・戦闘の横向き倍率を0.85へ統一し、各方向52×0.85＝44.2pxにする。
- 親コマンドメニューの専用パッドは1辺44pxの実サイズとし、縮小を行わない。大きさのみ調整し、フィールドのキャラ倍率・カメラ・衝突判定には触れない。ノッチ・画面端・会話ボックスとの非重複はChromeとiPhone実機で継続確認。

- 共通UIの回帰防止：`src/game/ui/controls.css`・親ゲームの`index.html`・回転案内コードの変更で、フィールド・村・社・戦闘のブラウザ検査が実行されるようGitHub Actionsのpaths条件を横断修正。従来はフィールド・戦闘QAが個別ソース変更時だけ走るため、共有CSSの変更が未検査になる欠陥があった。

## 描画時間の計測（2026-11-14）
- `src/field/?from=village&profile=1` のときだけ `window.__FIELD_RENDER_PROFILE` に1回の描画時間（実行ミリ秒、240サンプル）・回数・キャンバス論理寸法を保持。通常のプレイ中は時計取得やサンプル蓄積なし。画面上のデバッグ表示なし。
- `tools/qa-field-browser.mjs` で横3サイズの静止時・短時間移動後の描画サンプルを取得しp50/p95/最大時間をGitHub Actionsログに出す。ヘッドレスChromiumの値はiPhone Safari実測FPSではないため、参考値として区別する。

## 描画最適化の比較と採否（2026-11-14）
- 初回Chrome計測：描画中央値103〜107ms（縦横サイズ3通り、ヘッドレスCI上の参考値）。
- `CanvasPattern` の三角形塗りつぶしは約213〜226msへ悪化。9引数の`drawImage`でUVの一部分を切り出す方式も約124〜146msへ悪化したため、**両方とも不採用**。
- 代替として元の3引数`drawImage`経路を維持し、繰り返し境界用パディングを元画像の3×3から**周囲16pxの幅だけ**へ限定できる通常地形に適用する。UVが原画像の外へ出る海岸・崖の描画は従来の3×3方式に戻す。これで画素の原点と画像の繰り返し規則を守りつつソース面積を縮小する。検査値で改善が確認できなければ元の描画へ戻す。
