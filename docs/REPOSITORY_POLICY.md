# 新リポジトリのフォルダ・素材管理方針

| 保存先 | 役割 | 入れてはいけないもの |
|---|---|---|
| `src/` | 採用中のゲームプログラム | 使い捨て試験コード・配信物 |
| `data/` | マップ・イベント・会話の構造化データ | 名前違いのコピー |
| `assets/` | 採用済みゲーム素材 | 未承認・比較・中間生成物 |
| `source-assets/` | 再編集が必要な採用素材の元データ | 完成画像の複製 |
| `.agents/skills/` | 再利用可能な手順の唯一の正本 | 重複・類似スキル |
| `docs/` | 現行設計と意思決定 | 旧版設計を現行と誤認させる資料 |
| `tools/` | 共通加工・検査スクリプト | 試作用の一時スクリプト |
| `tests/` | 自動検査 | テストの生成結果 |
| `work/` | 一時作業（Git管理外） | 採用素材の唯一の正本 |

空フォルダを `.gitkeep` で大量に作らず、実際に使う際に新設する。`old/` に旧実装を丸ごと保管せず、Git履歴または元リポジトリを利用する。

## 採用手順
1. `assets/manifest.json` と既存のファイルを検索し、重複を確認。
2. 再利用・画像加工で対応できるか検討。必要なら `work/` で試作。
3. ユーザーの承認と品質検査が済むまで `assets/` に入れない。
4. 採用されたファイルを用途別の安定パスへ**1つだけ**保存し、台帳へID・パス・型・採用状態を記入。
5. 再編集が必要な原本だけ `source-assets/` に登録し、台帳の `sourcePath` とリンク。
6. `npm test` とゲーム内の見た目・動作を別々に検査してから報告。改訂時は同じ正本パスを更新し、旧版はGit履歴へ残す。

## 素材台帳の記入例
以下は**例示**であり、現時点で採用されている素材ではありません。

```json
{
  "schemaVersion": 1,
  "assets": [
    {
      "id": "hizuki-idle",
      "type": "character",
      "path": "assets/characters/hizuki/idle.png",
      "status": "approved",
      "sourcePath": "source-assets/characters/hizuki/idle-source.png"
    }
  ]
}
```

`sourcePath` は原本が必要で**実際に保存する場合だけ**付ける。任意に `origin`、`license`、`approvalNote` 等の追跡情報を追加できる。`path` は常にリポジトリ相対パス。

## 自動検査と限界
`tools/check-repository.mjs` は、怪しい旧版/一時保管先、未登録素材、素材IDとパスの重複、ファイル不在、採用素材・原本の完全一致重複を検出する。**見た目の近似重複・画質・ライセンス・ゲーム動作・iPhone Safari**については別途検査する。

GitHub Actionsはpush後に検査するため、直接mainへコミットした内容を事前にブロックしない。
