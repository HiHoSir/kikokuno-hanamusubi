# 海の入り江 — 合格済み海岸を本編に再現する制作記録

## 絶対に混同しない
- **地形と景観の基準**：`previews/shoreline-study/?v=a092326`（コミット `a092326b`、ユーザーの外観合格済み）。
- **本編**：`data/maps/sea-cove/scene.mjs`、`src/game/cove/render.mjs`、`walk.mjs`。上記の基準を満たすよう作り直す対象。以前の46×34・東側が海・大きな森と草地を持つ入り江は採用基準ではない。
- **全体フィールド**：`src/field/`、`data/maps/field/`。今回の入り江制作では地形・高さ表現・遠近カメラなどを**変更しない**。既存のフィールド用地形エンジンを本編入り江から参照することはできるが、フィールドのソースの勝手な改変を意味しない。

## 現在の制作方針（ユーザーの外観レビュー待ち）
- 承認済み試作の30列 `SHORE_Y` を `data/maps/shoreline-study/scene.mjs` から直接読み込み、海は上側（北）。**東側12列と南側22行を拡張して42×44マス**にする。以前の30×22マスの地形は全セル保持。既存30列の北海岸線を一切変更せず、東の12列は32pxマップチップで連続する海岸形状を設計し、16形状の海岸チップと8コマ波を追加列にも同じ規則で適用。元の58波チップは既存範囲の基準であり、**拡張後の総枚数を58枚に固定しない**。開始座標・開始時の画面構図は変更しない。南端・東端は乾いた陸地／海岸がその先も連続する境界として描画し、地図境界を偽の波打ち際に変えない。**景観・配置は制作途中として改善可能。**
- **承認済み表示の退行防止**：海岸の8コマ波は16角マスクを跨ぐ部分も含めて**58枚の32pxアニメチップ**を使用する。海・砂を分類する粗いセル文字だけで境界チップを落とさない。開始位置は検査合格時と同じ `(336,432)` とし、画面内の海岸位置を勝手に変えない。2026-11-18に、本編側で13枚を落とし開始位置を32px動かした不一致を修正した。
- 地表は合格済み試作と同じ `window.YK_LANDSCAPE.groundLayer(dryMap)` の原寸32px砂浜。既存 `coast-mask-32.png` と4種の `coast-sand-{0,1,2,3}-32.png` を16角で接続。水面は独立レイヤー `water-motion.png` の64×64・2コマを360ms同期更新。8コマ寄せ引き波も共通の `src/game/terrain/surf.mjs` を使い、**北側の海から南の砂地へ**ワールド座標の連続した距離で動かす。
- 合格済みの**原寸岩3点を座標ごと流用**。勝手な草地帯・濃い森・野花で埋めない。村用80×112px緋月は原寸を維持。カメラ倍率は試作と同じ1.18を適用。
- 潮平は男性の漁師。`assets/characters/npc/ushiohei-walk-4dir-80x112.png` の専用12コマ（4方向×3枚、足元アンカー40,106）で描画する。女性の汎用 `villager-walk-4dir-80x112.png` は使用しない。実画像は承認済み男性 `farm-worker` を独自に加工し、笠・藍色の漁師装束・縄の意匠を持たせた。『天外魔境ZERO』のNPC画像は頭身・描画密度・歩行の参考のみであり画素は流用しない。制作手順は `tools/generate-ushiohei-sprite.py` に保存する。iPhone Safariでの見た目はユーザー確認待ち。
- **漁師の生活場（2026-11-18 拡張）**：南西に既存村素材 `assets/village/scene/house-thatch.png`（原寸390×357px、非入室）を配置し、南東に木枠干し網（192×150px）、畳んだ網（112×66px）、縄束（68×50px）をそれぞれ別透過PNGで配置。箱・樽・かごは既存承認素材を使う。網は `tools/generate-cove-fishing-gear.py` で自作（原作『天外魔境ZERO』の小物の画素は転用しない）。大きさ・視点・輪郭・ドット密度を村の素材に合わせる。家の屋根と網には個別の接地面ベースの当たり判定を持たせる。屋根画像のRGBAで衝突を判断しない。古い30×22のマップ領域に新しい建物や漁具を重ねない。家の原寸画像も屋根上端がY=783以南となるようにし、南側新エリアに収める。南出口と貝殻採集地点への歩行導線を確保する。
- **縮尺の違い（要注意）**：緋月は村・入り江とも同一の原寸80×112px／足元 (40,106)。家・網・緋月は個別倍率なし。ただし2026-11-18時点で村のカメラ倍率は `0.5`、入り江の承認済み構図は `1.18` であるため、同じ端末の画面上では**入り江の緋月が村の約2.36倍に見える**。画面倍率を同一にする変更は、この合格済み構図を変えるので本拡張には含めない。『村と画面上の緋月サイズが同じ』とは報告しない。
- 南出口・潮平・かご・樽は本編のイベント機能として置き直す。貝殻の固定採集地点は合格済み試作の16点を使い、本編のプレイヤー保存情報・茶店買取機能とつなぐ。戦闘5回ごとにランダム1〜3個（配置場所は固定）。
- 本編の入口はフィールドの既存 `cove` 接触セル。フィールド側は変更しない。入退場・会話・セーブの動作は既存の `KIKOKU_ROUTE` と親ゲームシェルを使用する。
- `previews/sea-cove-review/` はこの本編の同じ描画・マップをiPhone Safariで歩いてチェックするための**GitHub Pages限定**ページ。レビュー操作で本編のセーブを更新しない。

## 検査・合格
- `tests/sea-cove.test.mjs` は承認済み海岸データとの同一性・岩の位置・砂浜の広さ・描画コードを検査。 `tests/cove-shells.test.mjs` は採集と売却、貝殻固定位置を検査。
- `tools/qa-sea-cove-browser.mjs` はChromiumで実シーンを読み、海が動くこと、緋月が歩けること、貝殻を拾えること、専用Pages画面のセーブ非更新を検証。
- 自動検査の成功＝外観合格ではない。**iPhone Safariで実際の動きを確認し、ユーザーが見た目を承認するまでは制作途中**。承認前でも `main` で試作・修正してよい。
- 今回の復旧作業と、許可なく外部CDNを使用した問題は別件。後者は `docs/EXTERNAL_CDN_INCIDENT.md` に未解決として記録する。
